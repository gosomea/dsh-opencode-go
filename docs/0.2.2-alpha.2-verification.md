# DSH 0.2.2-alpha.2 compatibility verification

On 2026-11-02, version 0.1.3 was checked with Node 24 and the DSH 0.2.2-alpha.2 checkout at `f3803c9697`. The package declares this Host version; compatibility with earlier releases is not asserted.

`npm run check`, `npm test` (26 tests), `npm run build`, and `npm run pack:check` passed. Local HTTP fixtures exercised session headers and the Completions, Responses, Anthropic, and Google request paths; a Completions fixture also verified a streamed text response and normal completion. Loader tests cover registration and disposal. These fixtures do not establish real provider inference or account eligibility.

A dedicated Web profile installed the source through `dsh plugin add link:`. Its running Host returned the public catalog, and the Models settings panel displayed 28 Go and 78 Zen entries; manual refresh completed. A separate clean test home installed the packed tarball through `dsh plugin add file:` and its Host returned the same catalog counts. An initial public refresh failed with a transient DNS error; a later refresh succeeded. Model counts and rates are snapshots, not account entitlements.

The clean tarball installation needed the same `allowBuilds: false` policy for `@google/genai@2.21.0` and `protobufjs@7.6.6` as the target Host workspace. Without it, pnpm rejected the ignored lifecycle scripts. No real OpenCode inference or paid model call was made.
